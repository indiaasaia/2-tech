2 · What "challenge each point" actually killed or changed

❌ Killed by measurement

  • e5 semantic scoring layer — cosine compressed into 0.80–0.84; no tunable threshold exists (V5)
  • "Just write a better prompt" — constrained generation still fabricated on attempt 1: gate→regenerate is mandatory (V7)
  • Analyst prompt patches alone — returned empty language requirements even when the JD said "ideally english and german" → deterministic post-check required (V7)
  • Gemini as load-bearing / NVIDIA as free critic / parallel LLM workers — free-tier realities (V2)
  • Truncation worry — 0/21 JDs truncated (V4)

✔️ Survived / strengthened

  • Parse fidelity as the #1 KPI — measurably 0/21 before fixes
  • KB + claimable-set generation — fabrication is systemic (201/201 triaged true positives), so this became THE central fix
  • Coverage scorer — intent 0.72 vs artifact 0.73 (+0.01): generation lands in the PDF
  • ESCO + alias map synonyms — deterministic, never misfires
  • Cross-encoder — kept only as advisory "best line for missing requirement" suggestions
Design reversal: embeddings were removed from scoring entirely. The score got simpler because measurement removed machinery — not because challenge added it.

Iteration & honesty rules

  • Regenerate only if score < 70 or required coverage < 0.8; max 2 iterations; accept only if score improves by > 2 with G2 clean
  • Honest coverage targets: current 0.73 is partly purchased with fabrication → expect honest 0.5–0.7; the ceiling is set by KB expansion, not prompt pressure
  • Genuinely missing requirements → gap report to you (learn it / skip the job) — never a fabricated claim

7 · The candidate knowledge base — the central fix

Structured JSON, schema-validated at load. Every skill has ≥1 evidence id; explicit skills_allowed / skills_forbidden per experience and project; projects are the real ones with real evidence only. The LLM may select, reorder, summarize, mirror surface forms — it may never exceed the KB. Fabrication becomes a compile error, not a prompt hope.

{
  "id": "soham",
  "titles_allowed": ["Software Engineer", "Backend Engineer", ...],
  "skills_allowed": ["backend engineering", "database management", ...],
  "skills_forbidden": ["docker", "kubernetes", "aws", "react", ...],
  "evidence": ["integrated backend systems, servers and databases ..."]
}
Why it's the central fix: V6 proved ~9.6 unlicensed tool claims per job and that the projects prompt instructs the fabrication. Prompt-level constraints reduce it ~4× but don't eliminate it (V7) — only KB licensing + gates do.

9 · The meta-lesson

The three most valuable findings — small-caps corruption, date invisibility, and the replacement-order bug — were all found by testing artifacts, never by reading code or web research. Two proposed designs (semantic scoring; "just constrain the prompt") died on contact with data. Rule going forward: every pipeline change is gated on build → extract → assert → ship.
